# Спецификация проекта (диаграммы)

## Диаграмма вариантов использования

<img width="753" height="1042" alt="diagram(6)" src="https://github.com/user-attachments/assets/02f3d78e-f475-4be4-b89e-84c591cdd356" />



**Акторы:**
- **Водитель** — просматривает свои заказы, свою машину, свой заработок.
- **Менеджер (администратор)** — управляет автомобилями, водителями, заказами, формирует отчёты, выполняет расчёты.

**Основные варианты использования:**
- Войти в систему
- Просмотреть свои заказы за период (*)
- Просмотреть свою машину (*)
- Просмотреть свой заработок (*)
- Управлять автомобилями (CRUD)
- Управлять водителями (CRUD)
- Управлять заказами (CRUD)
- Отчёт по водителю за период
- Отчёт по машине (пробег, масса)
- Отчёт по каждому водителю (поездки, масса, деньги)
- Найти водителя с минимум поездок
- Найти машину с максимум пробега
- Проверка грузоподъемности (триггер)
- Расчёт денег всем водителям за период
- Расчёт денег указанному водителю за период

## Диаграмма классов

<img width="625" height="750" alt="diagram (2)" src="https://github.com/user-attachments/assets/62e25ce4-988f-4a23-b292-cdf9c4f4fbbe" />


**Структуры данных:**
- `Car` — автомобиль (id, номер, марка, пробег, грузоподъемность)
- `Driver` — водитель (id, табельный номер, фамилия, категория, стаж, адрес, год рождения)
- `Order` — заказ (id, дата, водитель, автомобиль, километраж, масса груза, стоимость)

**Связи:**
- Один водитель может иметь много заказов (1 : many)
- Один автомобиль может иметь много заказов (1 : many)

## Диаграмма последовательности (водитель → просмотр заказов)

**Объекты:** Driver, UI, Service, DB

**Взаимодействие:**
1. Водитель открывает "Мои заказы"
2. UI запрашивает заказы у Service
3. Service выполняет SELECT * FROM Orders WHERE driverId=...

## Диаграмма последовательности (админ → сохранение заказа)

<img width="1500" height="695" alt="diagram (4)" src="https://github.com/user-attachments/assets/2ba27e0c-053e-4e47-b1b4-2fb8c2779d20" />


**Объекты:** Admin, UI, Service, Validator, DB

**Взаимодействие:**
1. Администратор сохраняет новый заказ
2. UI передаёт данные в Service
3. Service вызывает Validator для проверки массы и данных
4. Validator возвращает OK
5. Service выполняет INSERT INTO orders...
6. DB возвращает SUCCESS
7. Подтверждение возвращается к администратору

## Диаграмма компонентов

<img width="1120" height="750" alt="diagram (5)" src="https://github.com/user-attachments/assets/79023144-2870-43b9-a2a8-23d62a91fe33" />


**Компоненты проекта:**
- `Project` — общая структура
- `Консольный интерфейс` — пользовательский интерфейс
- `AuthModule` — аутентификация и авторизация
- `CarsModule` — управление автомобилями
- `DriversModule` — управление водителями
- `OrdersModule` — управление заказами + функции расчёта
- `SQLite` — база данных

**Связи:** все модули используют SQLite через слой работы с БД.
